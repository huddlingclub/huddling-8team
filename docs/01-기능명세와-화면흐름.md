# 01. 기능 명세와 화면 흐름

- 작성일: 2026-11-14 · 상태: 초안 v0.1 (MVP)
- Figma: [보드](https://www.figma.com/board/3lkLjEz5CKOm9OWVbxQilW/%ED%97%88%EB%93%A4%EB%A7%81-%ED%81%B4%EB%9F%BD-8%EC%A1%B0) — "씻을까? 사용자 플로우"(흐름도), "씻을까? 화면 설계 초안"(와이어프레임 5장)

## 1. 사용자 흐름

```
온보딩 1 (나갈 시각·필수 준비) → 온보딩 2 (씻기 체크리스트) → 홈 ("씻을까?") → 결과
                                                              ↑                │
                                                              └── 처음으로 ────┘
홈/결과의 [설정] → 온보딩 1부터 다시 수정
```

- 설정은 브라우저(localStorage)에 저장되어, 다음 방문부터는 **홈에서 바로 시작**합니다.
- 설정이 없거나 깨져 있으면 온보딩으로 돌아갑니다.

## 2. 화면별 명세

| # | 화면 | 핵심 요소 | 동작 |
| --- | --- | --- | --- |
| 1 | 온보딩 · 고정 시간 | 나갈 시각, 필수 준비 목록(이름·분), 합계 | 분 ±1, 삭제, 추가. [다음]에서 검증 |
| 2 | 온보딩 · 씻기 체크리스트 | 체크박스, 순번(우선순위), 분 ±1, ↑↓, 삭제, 추가 | 체크 = 후보 포함. 위쪽일수록 우선순위 높음. [설정 완료]에서 검증 후 저장 |
| 3 | 홈 | 현재 시각, 출발 시각, 출발까지 남은 분, **씻을까?** 버튼 | 15초마다 시각 갱신. 버튼 → 계산 → 결과 |
| 4 | 결과 | 상태 칩, 코스 이름, 한 줄 안내, 준비 완료 예상·여유, 할 수 있는/포기 항목, 꼬질도, 재촉 문구, 말투 토글 | 숫자·항목은 즉시, 문구는 AI(최대 2.5초) 또는 기본 문구 |

## 3. 결과 상태 5종

같은 레이아웃을 상태에 따라 재사용합니다. (`app.js` → `calculatePlan`의 `status`)

| status | 조건 | 상세 줄 | 코스 이름 예 (기본 문구) |
| --- | --- | --- | --- |
| `full` | 후보 항목 전부 가능 | `08:30 준비 완료 예상 · 출발까지 10분 여유` | 왕족 목욕 코스 |
| `partial` | 일부만 가능 | `08:38 준비 완료 예상 · 출발까지 2분 여유` | 머리 감기까지 사수 코스 |
| `none` | 필수 준비는 되지만 씻기는 0개 | `… · 출발까지 N분 여유` | 고양이 세수도 사치 코스 |
| `short` | 필수 준비 시간도 부족 | `출발까지 N분 부족` | 일단 뛰어 코스 |
| `passed` | 출발 시각이 이미 지남 | `HH:MM 출발 시각 지남` | 이미 늦었다 코스 |

## 4. 계산 규칙 (자세한 알고리즘은 02 문서)

1. `남은 시간 = 출발 시각 − 현재 시각`
2. `씻을 수 있는 시간 = 남은 시간 − 필수 준비 합계`
3. 우선순위 순으로 항목을 더해 가며 **씻을 수 있는 시간을 넘지 않는 항목까지만** 포함 (기본: 처음 안 들어가는 항목에서 멈춤)
4. `준비 완료 예상 = 현재 시각 + 필수 준비 + 포함된 씻기`, `여유 = 남은 시간 − 필수 준비 − 포함된 씻기`
5. `꼬질도(%) = (1 − 한 항목의 cleanPoints 합 / 활성 항목의 cleanPoints 합) × 100`

| 꼬질도 | 단계 |
| --- | --- |
| 0~10 | 반짝반짝 ✨ |
| 11~35 | 말끔 🫧 |
| 36~60 | 무난 🙂 |
| 61~85 | 꼬질 🐿️ |
| 86~100 | 동굴 거주자 🦧 |

## 5. 입력 검증

| 대상 | 규칙 | 실패 시 |
| --- | --- | --- |
| 나갈 시각 | `HH:MM` 형식 | "나갈 시각을 HH:MM 형식으로 입력해줘." |
| 필수 준비 | 1개 이상 | "필수 준비를 하나 이상 추가해줘. (예: 옷 입기)" |
| 항목 이름 | 비어 있지 않음, 12자 이내 | "이름과 1~120분 사이의 시간을 입력해줘." |
| 소요 시간 | 정수 1~120분 | 같은 문구 |
| 씻기 항목 | 체크된 항목 1개 이상 | "씻기 항목을 하나 이상 체크해줘." |

## 6. AI 문구 (요약)

| 앱 → 서버 | 서버(AI) → 앱 |
| --- | --- |
| 남은 시간, 필수 준비 분, 여유/부족 분, 준비 완료 시각 | `summary` 상황을 설명하는 한 줄 |
| 가능한 항목(이름·분) | `courseName` 재미있는 코스 이름 |
| 제외된 항목(이름·분) | `giveUpNote` 포기해야 하는 항목 안내 |
| 말투(`sweet` 다정한 / `playful` 장난스러운) | `nudge` 여유 정도에 맞는 재촉 문구 |

- 화면의 **시간·항목은 항상 앱 계산값**. AI 응답은 문구 4종에만 쓴다.
- AI가 계산에 없는 숫자(시각·분)를 말하면 서버가 버리고 기본 문구로 대체한다.
- 응답이 2.5초 안에 없으면 기본 문구. 결과 숫자는 AI를 기다리지 않고 즉시 보인다 (문구 영역만 잠깐 흐리게).

## 7. QA 체크리스트 (QA·UX 라이팅 담당용)

홈 화면의 **"테스트용: 현재 시각 바꿔보기"** 로 시각을 바꿔 확인하세요. (기본 설정: 출발 08:40, 필수 준비 10분, 씻기 30분)

| 확인할 상황 | 현재 시각 | 기대 결과 |
| --- | --- | --- |
| 시간이 넉넉함 | 07:50 | `full`, 10분 여유, 꼬질도 0% |
| 기획서 예시 | 08:15 | `partial`, "머리 감기까지 사수 코스", 08:38 완료·2분 여유 |
| 씻기만 불가 | 08:28 | `none`, 씻기 0개, 꼬질도 100% |
| 필수 준비도 부족 | 08:32 | `short`, "출발까지 2분 부족" |
| 출발 시각이 지남 | 08:45 | `passed`, "08:40 출발 시각 지남" |
| 딱 출발 시각 | 08:40 | `passed` (정각은 지난 것으로 처리) |
| 자정 넘김 | 출발 시각 00:30, 현재 23:50 | 남은 40분으로 계산 (`full`, 여유 0분) |
| 입력 누락 | 온보딩에서 시각 비우기 / 필수 준비 전부 삭제 / 체크 전부 해제 | 각 오류 문구 표시, 다음 화면으로 안 넘어감 |
| AI 실패 | 서버 없이(더블클릭 또는 `http.server`) 실행 | 기본 문구, 출처에 "기본 문구" 표시, 화면이 멈추지 않음 |
| 말투 변경 | 결과 화면에서 토글 | 문구만 바뀌고 숫자·항목은 그대로 |
| 모바일 | 폭 360~430px | 가로 스크롤 없음, 버튼 44px 이상 |
