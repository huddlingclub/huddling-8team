# 03. 팀 피드백 안건

2시간 안에 만들려고 **일단 이렇게 가정하고 구현한 것들**입니다. 틀렸다고 생각되면 바로 말해 주세요. 바꾸는 비용도 같이 적었습니다.

우선순위: 🔴 구현 전에 정해야 함 · 🟡 데모 전에 정하면 좋음 · ⚪ 시간 남으면

## 🔴 먼저 정해야 하는 것

### 1. 씻기 항목을 어떻게 채울까? (기획·기능)

현재: **우선순위 순서로 채우다가 처음 안 들어가는 항목에서 멈춤** (`strict`).

| | strict (현재) | greedy |
| --- | --- | --- |
| 예 (가용 11분) | 세수·양치 (6분)에서 멈춤 | 세수·양치 + **머리 말리기**(5분) |
| 장점 | 우선순위가 그대로 지켜짐, 코스 이름("머리까지 사수")이 자연스러움 | 시간을 더 알뜰히 씀 |
| 단점 | 남는 시간이 아까울 수 있음 | **머리를 안 감았는데 말리기**가 나올 수 있음 |

바꾸는 비용: `data.js`의 `FILL_STRATEGY` 한 줄. greedy를 쓴다면 "머리 말리기는 머리 감기가 있어야 함" 같은 **의존 관계(`requires`)**도 같이 정해야 합니다.

### 2. AI는 어떤 걸 쓸까? 키는 누가? (팀장·기능)

현재 가진 키는 카카오맵(JS·REST)뿐이라 **AI 키가 없습니다.** 지금은 `claude-haiku-5-5`(Anthropic)를 가정해 `api/message.js`를 짜 뒀고, 키가 없으면 기본 문구로 동작합니다.

- 제공자·모델·키 발급 담당 정하기 (비용 한도 포함)
- 다른 제공자를 쓰면 `AI_ENDPOINT`·헤더·응답 파싱만 바꾸면 됩니다 (1개 파일)
- 발표 때 AI 문구가 꼭 나와야 하는지? 기본 문구만으로도 시연은 가능합니다

### 3. 말투는 어디서 고를까? (기획·디자인)

현재: **온보딩에는 없고 결과 화면에서 토글** (다정하게 / 장난스럽게). 기본값은 장난스럽게.

- 선택지: ① 결과 화면 토글만 (현재) ② 온보딩에서 선택 ③ 둘 다
- 말투를 늘릴지(예: 츤데레, 군대식)? 프롬프트에 설명 한 줄 + `data.js` 기본 문구만 추가하면 됩니다

## 🟡 데모 전에 정하면 좋은 것

### 4. 이동 시간도 계산에 넣을까? (기획)

지금은 "집에서 나갈 시각"을 사용자가 직접 입력합니다. 카카오 **길찾기** API를 쓰면 "도착 시각 − 이동 시간 = 나갈 시각"을 자동 계산할 수 있어 보유한 카카오 키를 살릴 수 있습니다. 대신 목적지 입력·권한·키 노출(REST 키는 서버에서만) 작업이 늘어서 **2시간 MVP에는 넣지 않았습니다.**

### 5. 꼬질도는 어떻게 정의할까? (기획·디자인)

현재: `꼬질도 = 활성 항목 중 못 한 cleanPoints 비율`, 5단계(반짝반짝 → 동굴 거주자). 세수 10, 양치 15, 머리 감기 25, 몸 씻기 25, 머리 말리기 15, 스킨케어 10 (합 100).

- 점수 배분이 맞는지? (예: 양치가 머리 감기보다 중요하다고 느끼는지)
- 사용자가 직접 추가한 항목의 기본 점수는 10으로 둠 — 온보딩에서 중요도를 입력받을까?
- 단계 이름·이모지·한 줄 코멘트(`data.js`의 `DIRTY_LEVELS`) 카피 검수

### 6. 출발 시각이 "이미 지난" 경우의 기준 (QA)

현재: 출발 시각이 **12시간 넘게 과거**면 "다음 날 출발"(자정 넘김)로 보고, 그보다 가까우면 "지남"으로 봅니다. 정각은 지난 것으로 처리.

- 08:00에 일어났는데 출발이 07:50이면 → "지남". 맞나요?
- 출발이 내일 아침인데 지금 낮 12시에 눌렀다면 남은 시간이 20시간으로 나옵니다. 이런 입력은 막을지(예: 남은 시간 상한)?

### 7. 시간이 너무 많이 남을 때 (UX 라이팅)

남은 시간이 넉넉하면 `full` 상태 하나로 처리합니다 ("풀코스 여유 만끽"). 여유가 30분 이상일 때 "한숨 더 자도 돼" 같은 **별도 상태**를 만들지? (재미 포인트가 될 수 있음)

### 8. 설정은 어디에 저장할까? (팀장·기능)

현재: 브라우저 `localStorage` (로그인 없음, 서버 DB 없음). 다른 기기에서 열면 설정이 사라집니다. 발표용 MVP에는 충분하다고 봤고, 서버 저장 설계는 [02 문서 6장](02-백엔드-데이터구조.md)에 따로 적어 뒀습니다.

## ⚪ 시간 남으면

### 9. 호출 남용·비용 (기능)

`/api/message`는 인증 없이 열려 있어 누가 반복 호출하면 AI 비용이 듭니다. 입력 검증·길이 제한은 있지만 **호출 횟수 제한은 없습니다.** 공개 URL로 발표하기 전에 IP별 제한이나 일일 상한을 둘지 정하세요.

### 10. 결과 다음 행동 (기획)

결과를 보여주고 끝납니다. "바로 시작" 버튼으로 **항목별 타이머**를 돌려 주면 서비스 완성도가 올라갑니다. (다음 스프린트 후보)

### 11. 디자인 확인 (디자이너)

- Huddling Club 다크 톤(발표 슬라이드와 맞춤) vs 라이트 톤
- 홈의 "테스트용 시각 바꾸기"는 개발·QA용 → 최종 디자인에서 숨길지
- 기본 문구/AI 문구 출처 표시를 사용자에게 보여줄지 (지금은 작은 회색 글씨)
- 글꼴·아이콘, 꼬질도 시각화(막대 vs 캐릭터)

### 12. 발표 시나리오 (기획·발표)

데모 시각을 어떻게 연출할지(실제 시각 vs "테스트용 시각 바꾸기"로 08:15 세팅), AI가 실패해도 화면이 멈추지 않는 점을 시연할지 정하면 좋습니다.
